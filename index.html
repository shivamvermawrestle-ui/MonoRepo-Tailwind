Get Started

How to run web and mobile

One install. Then start the website, the phone app, or both — from the same repository.

01

Clone & install

One `yarn install` at the repo root installs every app and package in the workspace.

yarn install
02

Run web and mobile

Stay in the same folder. yarn web starts Next.js at localhost:3000. yarn android or yarn ios starts Expo. Same shared code — pick the platform you want to preview.

yarn web
03

Extend packages

Add features under packages/shared_mono_app and import them from both apps — no second repo.

yarn api myFeature

Why monorepo

Built for teams who ship web and mobile together

Ship web and mobile from one workspace — without duplicating components, configs, or installs..

Write once, ship twice

Shared UI, state, and API clients import into Next.js and Expo. Fix a bug once — both platforms get the update.

Type-safe across packages

TypeScript path aliases connect every package. Refactors stay consistent from `packages/ui` to `apps/mobile`.

Faster CI & local builds

Turborepo caches task outputs. Re-run `turbo build` or `turbo lint` and only changed packages rebuild.

Workspace

Folder layout at a glance

Applications stay in `apps/`. Reusable code lives in `packages/`. Turborepo connects builds and dev scripts across both.

FAQ

Monorepo questions

Short answers about this workspace template.

What ships in this template?

A Turborepo monorepo with apps/web, apps/mobile, shared packages, and a landing page.

How do I add a new package?

Create a folder under `packages/`, register it in the root workspace config, then import it from your apps.

Can I use only web or only mobile?

Yes. Run the web app alone, the mobile app alone, or both — shared packages work with either target.

Where should new features go?

Put reusable logic in `packages/shared_mono_app` or a new package. Keep `apps/*` focused on routing and app wiring.
